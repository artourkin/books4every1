# Folio API v1

Base path: `/api/v1`. Responses use JSON except files/covers and `204 No Content`. Errors return `{"error":"message"}` with an appropriate HTTP status. Missing resources return 404; invalid payloads 400; unsupported file types 415; invalid archives 422; oversized uploads 413. There is currently no pagination. IDs are random hex strings generated by the server.

## Authentication

For accounts, `POST /session` with `{"username":"alex","password":"…"}` sets an HttpOnly, SameSite=Strict cookie for 30 days. `GET /session` returns `authenticated`, `passwordRequired`, `accountsEnabled`, and `user` (null before accounts are enabled). Authenticated responses also contain `profileId` and the full `preferences` object. Account sessions have opaque random tokens; only their SHA-256 hashes are stored. `DELETE /session` revokes the current account session and clears its cookie. Password changes/resets revoke previous sessions; changing your own password issues a replacement session.

Before the first owner account is created, the legacy `{"password":"…"}` login and signed-cookie mechanism remain available. A configured `FOLIO_PASSWORD` is required for access and owner creation; without one, trusted-network access is enabled until owner setup. The first `POST /users` creates an administrator and replaces the caller's legacy cookie with an account session. Its legacy-profile server preferences are copied to the owner. Afterward all protected endpoints require an account session or the server API token, and legacy signed cookies no longer authorize access. `FOLIO_PASSWORD` cannot bypass account login.

Native clients/scripts may send `Authorization: Bearer <FOLIO_API_TOKEN>`. This credential has administrator and full shared-library access; with accounts enabled its preferences belong to the earliest remaining administrator. It is a server credential, not a per-user token. No CORS policy is enabled. Browser writes must have an Origin matching the request Host; a reverse proxy must preserve Host. Non-browser clients can omit Origin. Session and health endpoints are public; other endpoints enforce the current access mode. Account passwords are 8–128 UTF-8 bytes; usernames are case-insensitive, 3–32 ASCII letters/numbers/dots/underscores/dashes, starting with a letter or number.

The books, reading state, collections, and annotations remain shared across accounts. Only preferences are private to each account.

```sh
curl -H "Authorization: Bearer $FOLIO_API_TOKEN" http://localhost:8080/api/v1/books
curl -H "Authorization: Bearer $FOLIO_API_TOKEN" -F file=@book.epub http://localhost:8080/api/v1/books
```

## Preferences

`GET /me/preferences` returns the current profile's settings. Partial PATCH requests preserve untouched fields even when another device saves different settings concurrently. The last successful write to the same field wins. Unknown fields, nulls, and invalid values return 400. The caller cannot select another user's profile. Browser clients send `X-Folio-Profile: <profileId from session>` with PATCH: a different currently authenticated profile returns 409, preventing an old tab from applying its settings after an account switch. GET/session responses omit preferences when unauthenticated.

Defaults:

```json
{
  "penWidth": 3,
  "markerWidth": 12,
  "inkColor": "#394137",
  "inkTool": "pen",
  "inkBrush": "pen",
  "drawWithTouch": false,
  "fontSize": 100,
  "theme": "paper",
  "highlightColor": "yellow",
  "libraryLayout": "grid",
  "librarySort": "recent"
}
```

Pen width: 1.5, 3, 5, or 8; marker width: 6, 12, 20, or 30. Ink color: six-digit hex. Tool: `pen`, `highlighter`, or `eraser`; brush: last drawing tool (`pen`/`highlighter`). Text size/page zoom: integer 70–180. Theme: `paper`/`night`; highlight color: `yellow`/`green`/`pink`/`blue`; library layout: `grid`/`list`; sort: `recent`/`title`/`author`/`progress`. Preferences do not change existing strokes; each stroke retains its original color, width, and pressure.

## Book

```json
{
  "id": "c53b7c21722850deabde03fe38acc16e",
  "title": "Walden",
  "author": "Henry David Thoreau",
  "format": "EPUB",
  "size": 21940,
  "cover": false,
  "color": "sage",
  "addedAt": "2026-11-09T12:00:00Z",
  "lastRead": "2026-11-09T13:00:00Z",
  "progress": 0.35,
  "location": "epubcfi(/6/2!/4/2:1)",
  "favorite": false,
  "status": "reading",
  "collection": "Nature",
  "sample": true
}
```

Editable fields: `title`, `author`, `favorite`, `status`, `collection`, `progress`, `location`. Status is `unread`, `reading`, or `finished`. Progress is a fraction in `[0,1]`. Updating progress sets `lastRead` and status (`finished` at >= 0.995; otherwise `reading`). Setting status alone leaves location/progress intact. Clients should send progress and location together. The web reader uses EPUB CFIs and 1-based page numbers serialized as strings for PDFs. Last successfully saved location wins; there is no conflict-resolution protocol yet.

Collection names are 1–80 bytes; title/author max 500 bytes. Title must be nonblank. Empty collection means unassigned. Collections must exist before assignment. Uploads accept files up to 100 MiB, verify PDF headers, and parse EPUB container/package data. EPUB archives are limited to 10,000 entries and 512 MiB declared expanded size. Covers are limited to raster JPEG, PNG, or WebP. EPUB resources are not extracted to server paths. No DRM decryption is performed.

## Annotation

Create with `kind`, `quote`, `note`, `color`, and `anchor`. The server assigns `id`, `bookId`, and `createdAt`. Kind is `highlight`, `bookmark`, or `note`; color is `yellow`, `green`, `pink`, or `blue` (unknown colors default to yellow). Quote/note are at most 50,000 bytes each. An anchor must contain an EPUB CFI or PDF page. CFI strings are at most 4096 bytes; rectangles are validated and limited to 1000 per annotation.

An EPUB highlight:

```json
{
  "kind": "highlight",
  "quote": "I went to the woods because I wished to live deliberately",
  "note": "Remember to make room for this.",
  "color": "green",
  "anchor": { "cfi": "epubcfi(/6/2!/4/2,/1:0,/1:55)" }
}
```

A PDF highlight:

```json
{
  "kind": "highlight",
  "quote": "A sentence worth keeping.",
  "note": "",
  "color": "yellow",
  "anchor": {
    "page": 3,
    "rects": [ { "x": 0.12, "y": 0.25, "w": 0.62, "h": 0.021 } ]
  }
}
```

PDF rectangle coordinates are fractions of the displayed, default-rotation page bounds, with `(0,0)` at the top-left. Render at any scale by multiplying by page width/height. A bookmark uses `anchor: {"page":3}` or `anchor:{"cfi":"epubcfi(...)"}`. Annotations are separate database records and do not modify original book bytes.


## PDF handwriting

Handwriting has its own page storage, separate from text annotations. `GET /books/{id}/ink/{page}` returns:

```json
{
  "page": 1,
  "revision": 0,
  "strokes": [],
  "updatedAt": null
}
```

A page with no stored ink has revision zero. Page numbers are 1-based. These endpoints accept PDFs only and use the same authentication and origin checks as other library APIs.

To save a page, `PUT /books/{id}/ink/{page}` with the last observed revision and the complete desired stroke list:

```json
{
  "revision": 0,
  "strokes": [
    {
      "id": "4511fe4f-0542-41ea-a299-1e2765e763cb",
      "tool": "pen",
      "color": "#394137",
      "width": 0.005,
      "points": [
        { "x": 0.1, "y": 0.2, "pressure": 0.35 },
        { "x": 0.4, "y": 0.3, "pressure": 0.8 }
      ]
    }
  ]
}
```

A successful save returns the page with an incremented revision and UTC `updatedAt`. The revision check and write happen in one transaction. A stale write returns **409** with `error` and `currentRevision`; it never replaces the saved page. Re-read the page and explicitly reconcile/discard local changes before retrying. Clearing a page uses an empty stroke array and retains its incremented revision to prevent resurrection by stale clients. Deleting a book also deletes its ink pages. Existing databases receive the new table automatically on startup; no book conversion is needed.

Coordinates `x`/`y` are normalized to `[0,1]` in the displayed PDF page's default rotation, top-left origin. `width` is a fraction of the page width, between `0.0002` and `0.1`. Re-render by multiplying x/width by page width and y by page height, preserving pressure values in `[0,1]`. The web client creates outlines with perfect-freehand: pressure thinning 0.45 for pen, constant width for highlighter, smoothing 0.6, streamline 0.35, simulated pressure disabled. Highlighter opacity is 0.3. Other clients can draw their own outlines from the same points.

Tool is `pen` or `highlighter`; colors must be six-digit hex (`#RRGGBB`). Stroke IDs are unique within a page and contain 1–64 ASCII letters, digits, `_`, or `-`. Each stroke contains 1–10,000 points. Limits per page: 5,000 strokes, 200,000 total points, and a 16 MiB request body. Invalid ink returns 400. The API does not parse the PDF to verify the supplied page exists; clients must use the PDF document's page count.

The recovery download is `{ "format": "folio-ink-v1", "page": 1, "strokes": [...] }`. To restore it using another client, read the current page revision, review the stroke list, and PUT its `strokes` with that revision. Do not send `format` or `page` in the PUT body. Handwriting is not yet embedded in downloaded PDF bytes or included in the Markdown notebook export.
