# Folio API v1

Base path: `/api/v1`. Responses use JSON except files/covers and `204 No Content`. Errors return `{"error":"message"}` with an appropriate HTTP status. Missing resources return 404; invalid payloads 400; unsupported file types 415; invalid archives 422; oversized uploads 413. There is currently no pagination. IDs are random hex strings generated by the server.

## Authentication

For browsers, `POST /session` with `{"password":"your password"}` sets an HttpOnly, SameSite=Strict cookie for 30 days. `GET /session` returns `{"authenticated":true,"passwordRequired":true}`. `DELETE /session` clears the browser's cookie. Changing the configured password invalidates all session signatures. Logout clears that browser's cookie; it is not server-side revocation of a copied cookie.

Native clients/scripts may send `Authorization: Bearer <FOLIO_API_TOKEN>`. This token has full library access. Configure both a password and API token when using tokens: leaving the password empty enables unauthenticated trusted-network access. No CORS policy is enabled. Browser writes must have an Origin matching the request Host; a reverse proxy must preserve Host. Non-browser clients can omit Origin. Auth and health endpoints are public; the remaining API requires authentication when a password is set.

```sh
curl -H "Authorization: Bearer $FOLIO_API_TOKEN" http://localhost:8080/api/v1/books
curl -H "Authorization: Bearer $FOLIO_API_TOKEN" -F file=@book.epub http://localhost:8080/api/v1/books
```

## Endpoints

| Method | Path | Request / result |
| --- | --- | --- |
| GET | `/health` | Status and version; no authentication |
| GET, POST, DELETE | `/session` | Authentication described above |
| GET | `/books` | Array of Book, newest imports first |
| POST | `/books` | Multipart field `file`; returns imported Book (201) |
| GET | `/books/{id}` | Book |
| PATCH | `/books/{id}` | Partial editable fields; returns Book |
| DELETE | `/books/{id}` | Deletes book, cover, and all annotations (204) |
| GET | `/books/{id}/file` | Original EPUB/PDF; supports HTTP Range; `?download=1` sets attachment disposition |
| GET | `/books/{id}/cover` | Extracted raster cover, or 404 |
| GET | `/annotations` | All annotations, newest first; optional `?bookId={id}` |
| POST | `/books/{id}/annotations` | Create Annotation (201) |
| PATCH | `/annotations/{id}` | `{"note":"updated text"}` (204) |
| DELETE | `/annotations/{id}` | Delete (204) |
| GET | `/collections` | Sorted array of names |
| POST | `/collections` | `{"name":"Nature"}` (201); duplicate name returns 409 |
| DELETE | `/collections/{url-encoded-name}` | Delete collection, keep/unassign books (204) |
| POST | `/samples` | Import six optional public-domain excerpts; returns newly added Books (201); existing sample titles skipped |

## Book

```json
{
  "id": "c53b7c21722850deabde03fe38acc16e",
  "title": "Walden",
  "author": "Henry David Thoreau",
  "format": "EPUB",
  "size": 21940,
  "cover": false,
  "color": "sage",
  "addedAt": "2026-11-09T12:00:00Z",
  "lastRead": "2026-11-09T13:00:00Z",
  "progress": 0.35,
  "location": "epubcfi(/6/2!/4/2:1)",
  "favorite": false,
  "status": "reading",
  "collection": "Nature",
  "sample": true
}
```

Editable fields: `title`, `author`, `favorite`, `status`, `collection`, `progress`, `location`. Status is `unread`, `reading`, or `finished`. Progress is a fraction in `[0,1]`. Updating progress sets `lastRead` and status (`finished` at >= 0.995; otherwise `reading`). Setting status alone leaves location/progress intact. Clients should send progress and location together. The web reader uses EPUB CFIs and 1-based page numbers serialized as strings for PDFs. Last successfully saved location wins; there is no conflict-resolution protocol yet.

Collection names are 1–80 bytes; title/author max 500 bytes. Title must be nonblank. Empty collection means unassigned. Collections must exist before assignment. Uploads accept files up to 100 MiB, verify PDF headers, and parse EPUB container/package data. EPUB archives are limited to 10,000 entries and 512 MiB declared expanded size. Covers are limited to raster JPEG, PNG, or WebP. EPUB resources are not extracted to server paths. No DRM decryption is performed.

## Annotation

Create with `kind`, `quote`, `note`, `color`, and `anchor`. The server assigns `id`, `bookId`, and `createdAt`. Kind is `highlight`, `bookmark`, or `note`; color is `yellow`, `green`, `pink`, or `blue` (unknown colors default to yellow). Quote/note are at most 50,000 bytes each. An anchor must contain an EPUB CFI or PDF page. CFI strings are at most 4096 bytes; rectangles are validated and limited to 1000 per annotation.

An EPUB highlight:

```json
{
  "kind": "highlight",
  "quote": "I went to the woods because I wished to live deliberately",
  "note": "Remember to make room for this.",
  "color": "green",
  "anchor": { "cfi": "epubcfi(/6/2!/4/2,/1:0,/1:55)" }
}
```

A PDF highlight:

```json
{
  "kind": "highlight",
  "quote": "A sentence worth keeping.",
  "note": "",
  "color": "yellow",
  "anchor": {
    "page": 3,
    "rects": [ { "x": 0.12, "y": 0.25, "w": 0.62, "h": 0.021 } ]
  }
}
```

PDF rectangle coordinates are fractions of the displayed, default-rotation page bounds, with `(0,0)` at the top-left. Render at any scale by multiplying by page width/height. A bookmark uses `anchor: {"page":3}` or `anchor:{"cfi":"epubcfi(...)"}`. Annotations are separate database records and do not modify original book bytes.
